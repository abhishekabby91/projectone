### Do not trust a hardcoded list — re-derive it

**An earlier version of this file listed `accounstone-seo-improvements` for
deletion. That branch has since gained commits and is no longer merged into
`main`.** Running the old command verbatim would have deleted unmerged work.
A branch list written down on Monday is wrong by Tuesday, so derive it at the
moment you run it:

```bash
git fetch origin --prune

# every remote branch fully contained in origin/main, minus any you are using
git branch -r --merged origin/main \
  | grep -v 'origin/main$' | grep -v HEAD \
  | sed 's|origin/||; s/^ *//' \
  | grep -v '^claude/' > /tmp/merged.txt

wc -l < /tmp/merged.txt   # expect ~15
cat /tmp/merged.txt       # read it before the next line
xargs -a /tmp/merged.txt git push origin --delete
```

`--merged origin/main` is the safety property that matters: a branch it lists
has every one of its commits already in `main`, so deleting it removes a label,
not work. Anything not on that list stays.
